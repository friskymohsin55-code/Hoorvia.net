SQL Query Cheat Sheet: Printable SELECT & Clause Guide

Every database question you will ever ask boils down to the same handful of clauses: SELECT picks the columns, FROM names the table, WHERE filters the rows, and ORDER BY sorts what comes back. Learn those four and you can read almost any query; add JOIN, GROUP BY, and HAVING and you can write the rest. The trouble is that the clauses look interchangeable until they are not. WHERE filters rows before grouping, HAVING filters after; a missing WHERE on an UPDATE changes every row in the table; and SELECT * feels harmless until it drags back columns nobody asked for and slows the query down. Guessing costs data and time. This printable chart lays out twelve SQL query building blocks with what each clause does, a working example, and the note that saves you from the classic mistake. 💡 Quick Tips

Always write WHERE with UPDATE and DELETE: A missing WHERE updates or deletes every row in the table. Write the WHERE clause first, test it with SELECT, then run the change.

Filter with WHERE, not HAVING: WHERE filters rows before grouping and is fast; HAVING filters after grouping and only works on aggregates like COUNT.

Frequently Asked Questions

What is the difference between WHERE and HAVING?

WHERE filters individual rows before they are grouped, while HAVING filters the groups after GROUP BY runs. Use WHERE for row conditions like price > 10 and HAVING for aggregate conditions like COUNT(*) > 5. You cannot use aggregate functions inside WHERE.

What does a JOIN do in SQL?

A JOIN combines rows from two tables using a shared column, usually an ID. An INNER JOIN returns only rows that match on both sides; a LEFT JOIN keeps every row from the left table and fills unmatched right-side columns with NULL. Pick the join that matches your question.

Why is my query slow?

Slow queries usually scan the whole table because a WHERE or JOIN column has no index, or SELECT * drags back columns nobody needs. Index the filtered column, select only the columns you use, and add LIMIT while testing. Check the query plan with EXPLAIN.
