SQL Window Functions: Printable Guide

Window functions calculate across rows without collapsing them: ROW_NUMBER numbers the rows, RANK orders them, LAG looks at the previous row, and a windowed SUM gives a running total — all while keeping every row in the result. The trap is confusing them with GROUP BY: GROUP BY collapses rows into one per group, while a window function keeps every row and adds a calculation beside it. The key is the OVER clause — PARTITION BY splits the rows into groups, ORDER BY orders them inside each group, and the function does the rest. This printable chart lists twelve window functions with syntax, what each does, and the example. Consult the live reference table below, or print the sheet and keep it by your terminal.

💡 Quick Tips

PARTITION BY is the grouper: PARTITION BY splits the rows into groups and the function restarts in each one. Without it, the window is the whole result.

Window functions keep every row: GROUP BY collapses rows into one per group; a window function keeps every row and adds a calculation beside it. Use windows for detail plus totals.

Frequently Asked Questions

What is the difference between RANK and DENSE_RANK?

RANK leaves gaps after a tie — two rows tied for first both rank 1, and the next ranks 3. DENSE_RANK does not leave gaps — the next row ranks 2. Use RANK for leaderboards, DENSE_RANK for top-N lists without gaps.

When should I use LAG instead of a self-join?

When you need the previous row's value — month-over-month change, days since the last order. LAG does it in one pass; a self-join needs a second scan of the table and is harder to read.

Can I use a window function in a WHERE clause?

No — window functions run after WHERE, so the database has not calculated them yet. Filter on a window result with a subquery or a CTE: compute the window in the inner query, filter in the outer one.
