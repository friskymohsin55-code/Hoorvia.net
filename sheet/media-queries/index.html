CSS Media Queries Cheat Sheet: Printable Responsive Guide

Responsive design breaks in one predictable place: the media queries. A site looks perfect on a laptop, then collapses on a phone because someone used a max-width where a min-width belonged, or hardcoded pixel breakpoints that miss half the devices on the market. The syntax itself is small — @media, a feature, a value — but the decisions behind it are not: which breakpoints to use, when to target orientation or dark mode, and how to handle devices without a mouse. This printable CSS media queries cheat sheet puts twelve essential query patterns on one page: the standard width breakpoints, orientation and dark-mode queries, reduced-motion and print handling, and high-DPI targeting. 💡 Quick Tips

Go Mobile-First: Write the base styles for phones, then add min-width queries upward. It keeps CSS smaller and fixes the 'max-width maze' for good.

Test at Breakpoints: Resize your browser slowly through each breakpoint instead of jumping between devices — you'll catch the layout cracks in between.

Respect Reduced Motion: Wrap every animation in prefers-reduced-motion: reduce. It's one query that makes your site kinder for thousands of visitors.

Frequently Asked Questions

What are the most common CSS breakpoints?

The practical set is 640px (large phones), 768px (tablets), 1024px (laptops), and 1280px (desktops). Use min-width queries so styles stack upward. Frameworks like Tailwind use exactly these values, which is why they feel familiar.

Should I use min-width or max-width in media queries?

Prefer min-width with a mobile-first approach: write the small-screen styles first, then add min-width queries for larger screens. Max-width works for desktop-first code but creates overlapping rules that are harder to maintain.

Can media queries detect dark mode?

Yes — @media (prefers-color-scheme: dark) matches when the user's OS is in dark mode. Use it to override colors, swap images, and soften heavy shadows, so your site adapts without any JavaScript.
